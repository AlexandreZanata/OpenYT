# OpenYT 4.2.1

This maintenance release fixes the stretched full-window startup loading bar bug, introduces a branded startup loading screen across desktop and Android, and optimizes application cold-start latency.

## Fixes and improvements

- **Branded startup loading screen:** replaces the unconstrained `LinearProgressIndicator(Modifier.fillMaxWidth())` previously placed directly inside a `fillMaxSize()` Material 3 `Surface` (whose `propagateMinConstraints = true` stretched the bar into a full-window oval before `coordinator.ready` completed). `StartupLoadingScreen` now presents the centered OpenYT icon tile, wordmark, localized status caption (`pt-BR` and `en`), and a bounded 5 dp animated gradient loading bar with a smooth `Crossfade` transition into the main shell.
- **Faster desktop cold start:**
  - Restricts `java.awt.Desktop.getDesktop()` (`APP_OPEN_URI`) registration to macOS so Linux and Windows no longer block `AWT-EventQueue-0` inside `XDesktopPeer.initWithLock`.
  - Decouples `DesktopDeepLinks` OS handler registration (`xdg-mime` / `reg`) from blocking UI readiness.
  - Launches database initialization and concurrent `SettingsController`, `DownloadCoordinator`, and `LibraryController` restoration on `Dispatchers.IO` in parallel with desktop window creation, deferring subscriptions, stale temp cleanup, recovery/backup reconciliation, and bundled tool cache warm-up until after UI readiness.
  - Consolidates SQLite schema detection and `PRAGMA user_version` lookup in `DriverFactory` into a single connection.
- **Faster Android cold start:** moves startup temporary-file cleanup off the main thread onto `Dispatchers.IO`, restores settings, queue, and library concurrently, and wires `uiReady` into `MainActivity` so the branded loading screen displays cleanly until restoration finishes.

## Downloads and signatures

Assets include the Android APK, Windows MSI/EXE, macOS DMG, Linux DEB/RPM/AppImage/Flatpak/Arch packages, the optional browser handoff ZIP, and per-platform CycloneDX inventories.

`SHA256SUMS.txt` carries a detached RSA signature verifiable with `release-signing-public-key.pem`. Windows installers do not carry an Authenticode signature and the macOS bundle is not notarized.
